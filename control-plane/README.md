# MC-IaaS Control Hub

Crie o frontend completo de um Control Plane para uma plataforma acadêmica de IaaS chamada MC-IaaS, especializada em provisionar e administrar servidores de Minecraft executados como máquinas virtuais em Compute Nodes.

IMPORTANTE: nesta primeira versão, implemente SOMENTE o frontend e use dados mockados/local state. Não crie backend real, banco, autenticação real, Supabase ou chamadas diretas a servidores. O objetivo é gerar uma interface completa e profissional que depois será conectada a uma API própria do Control Plane.

CONTEXTO DO PRODUTO
O MC-IaaS é uma mini-plataforma de infraestrutura como serviço. Um Control Plane coordena Compute Nodes remotos. Cada Compute Node executa um Compute Agent que gerencia VMs com libvirt/KVM, runtime de rede, storage, health, métricas e recovery. Cada VM representa um servidor de Minecraft.

O frontend deve enxergar apenas abstrações de alto nível: Compute Node, Instance, Capacity, Runtime, Health, Metrics, Lifecycle e Recovery. Não exponha detalhes de libvirt, QCOW2, iptables ou DHCP como conceitos centrais da UX.

ESTILO VISUAL
Quero um dashboard de infraestrutura moderno, sóbrio e técnico, inspirado em consoles de cloud e observabilidade, mas sem copiar nenhuma marca específica. Visual dark-first, elegante, boa densidade de informação, excelente hierarquia, tipografia limpa, cards discretos, tabelas profissionais e gráficos pequenos. Evite estética gamer infantil. Minecraft deve aparecer como workload/serviço, não como tema visual predominante.

Use React + TypeScript + Tailwind + shadcn/ui, conforme o stack padrão do Lovable. Interface responsiva para desktop e tablet, com desktop como prioridade.

ARQUITETURA DO FRONTEND
Organize o projeto para facilitar futura integração com uma API real:
- components/
- pages/
- features/nodes/
- features/instances/
- features/monitoring/
- lib/
- mocks/
- types/

Crie uma camada de services/api abstraída mesmo que, nesta etapa, ela use adapters/mock services. Não faça fetch direto dentro de componentes. Isso será substituído posteriormente por um client real do Control Plane.

UX
- skeleton loading visual
- empty states
- error states mockáveis
- toasts
- dialogs
- tooltips em métricas menos óbvias
- badges consistentes para health/state
- não usar excesso de cores
- indicadores de estado devem ser claros mesmo sem depender apenas de cor

IMPORTANTE SOBRE SEGURANÇA
Não coloque tokens, credenciais ou IPs públicos reais no código. Use apenas valores fictícios/mockados. Não crie campos que revelem secrets.

RESULTADO ESPERADO
Quero uma primeira versão navegável e visualmente refinada do frontend completo do MC-IaaS Control Plane, pronta para ser posteriormente exportada para GitHub e integrada à nossa API real. Priorize consistência visual, arquitetura limpa e UX de dashboard técnico em vez de implementar backend.
